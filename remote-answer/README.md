# 在聊天里审批

agent 在等你**审批**（跑命令、改文件）或**回答问题**，你又不在电脑前时，把它发到你的聊天里；你在那边回一个数字，
agent 接着跑。

```
🔔 修登录（claude）在等你审批：Bash: rm -rf build
    rm -rf build
回复：1 允许一次 · 2 总是允许 · 3 拒绝
> 1
✓ 允许一次，它接着跑了
```

## 它不认识任何聊天工具

它和聊天之间只隔着 Gerdr 的事件：任何把私信变成 `<来源>/dm` 事件、并带上回复地址的插件都能用。现在有 [Slack](../slack)，
以后的飞书插件照这个样子发事件，不用改这里。

- **发到哪个聊天**：设置里的下拉框选。列的是装了的、能收发私信的聊天插件（Gerdr 按它们 addon.json 的 `emits` 列出来），
  不能留空；只装了一个就默认是它。
- **发到哪个对话**：选好聊天后，先给那边的 bot 私信一句（随便说什么），它就记住这个对话；换个对话私信，就跟着换过去。
  每个聊天各记各的，在插件数据目录的 `homes.json`。别的聊天里的私信它不管。
- **怎么回**：审批回编号，或者「允许 / ok」「拒绝 / no」；问题回选项编号（多选题可以回几个：`1 3`），能自己写答案的直接写；
  「跳过」不回答。一次只问一个，处理完再发下一个。
- **在电脑前处理掉了**：它会在聊天里说一声「已经在别处处理了」，接着问下一个。
- **免打扰的分组**里的会话不会发。

## 设置

| 设置 | 默认 | |
|---|---|---|
| 发到哪个聊天 | 第一个装了的 | 下拉选；没有可选的就先装一个聊天插件 |
| 多久没处理才发 | 60 秒 | 在电脑前通常一会儿就点掉了；过了这么久还在等才发。0 = 马上发 |
| 发到聊天里 | 开 | 关掉就不发新的（发出去的还能回） |

## 要知道的

- **它能替你批准命令。** addon.json 里写了 `"pending": true`，Gerdr 才把待处理的请求交给它、让它回答；你装它就是把这个权力
  交给了那个聊天对话。所以聊天插件那边一定只收自己的消息（Slack 插件设置里的「只收这些人的消息」填上自己的 ID）。
- 你在私信里回的数字，别的也订阅了 `slack/dm` 的面板（比如任务看板）一样会收到；它们得自己忽略。
- 需要 Node 22+。
